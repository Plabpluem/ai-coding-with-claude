# Intent: รายงานจุดน้ำท่วมจากคนในพื้นที่

> เอกสารนี้ Claude ร่างจากโค้ดใน repo และคำตอบที่ Claude เสนอเอง
> เจ้าของฟีเจอร์ยืนยันแล้ว 2 เรื่อง คือ ผู้อ่านหลักคือคนที่เข้ามาใช้งานแอป และจุดสังเกตเป็นข้อความอิสระ
> ข้อที่ยังเป็นสมมติฐานจะเขียนกำกับว่า **(สมมติฐาน)** และมีคำถามรออยู่ใน Open questions

## Problem

- คนกรุงเทพฯ ไม่รู้ว่า**ถนนหรือซอยที่จะผ่าน**มีน้ำท่วมจริงไหมและลึกแค่ไหน ตอนนี้แอปแสดงได้แค่ระดับน้ำในคลองจากสถานีวัด ซึ่งบอกไม่ได้ว่าน้ำบนถนนลึกเท่าไร
- สถานีวัดมีน้อย บางเขตไม่มีเลย เช่น สายไหม (`GET /districts/sai-mai` ได้รายการสถานีว่าง) คนในเขตนั้นจึงไม่ได้ข้อมูลอะไรจากแอปเลย
- คนที่อยู่หน้างานเห็นน้ำท่วมก่อนใคร แต่ตอนนี้ไม่มีที่ให้บอกต่อในแอป

## Proposed outcome

**ผู้อ่านหลัก:** คนที่เข้ามาใช้งานแอป อ่านรายงานเพื่อตัดสินใจว่าจะเดินทางผ่านจุดนั้นภายใน 1–3 ชั่วโมงข้างหน้าหรือไม่ **(สมมติฐาน: เหตุผลที่อ่าน)**

ทำเสร็จแล้วจะเปลี่ยนไปดังนี้

- คนในพื้นที่ส่งรายงานได้ 4 ช่อง
  - **เขต:** ต้องเป็น 1 ใน 12 เขตใน `src/districts.ts`
  - **จุดสังเกต:** ข้อความอิสระ ระบุสถานที่สาธารณะ เช่น แยกหรือถนน ความยาวไม่เกิน 100 ตัวอักษร **(สมมติฐาน: ความยาว)** พร้อมคำแนะนำว่าห้ามใส่บ้านเลขที่
  - **ความลึก:** จำนวนเต็มหน่วยเซนติเมตร
  - **เวลาที่เห็น:** รับเป็นเวลาที่ระบุ timezone และเก็บเป็น UTC
- `GET /districts/:id` แสดงรายงานที่ยังไม่หมดอายุควบคู่กับระดับน้ำของสถานีวัด ทุกรายงานมีข้อมูลดังนี้
  - ระดับความรุนแรง 3 ระดับตามคู่มือ คือ 1–20, 21–50 และมากกว่า 50 ซม. (ไม่ใช้ 4 ระดับใน tag `cp5-loop` ขึ้นไป)
  - ป้ายว่าเป็นรายงานจากประชาชน ไม่ใช่ประกาศทางการ
  - เวลาแสดงเป็นเวลากรุงเทพฯ
- รายงานแสดงทันทีโดยไม่ต้องมีคนตรวจก่อน **(สมมติฐาน)** และหมดอายุเมื่อเวลาที่เห็นผ่านไปนานเกินกำหนด **(สมมติฐาน: 3 ชั่วโมง)**
- ไม่เก็บชื่อหรือเบอร์โทรของผู้รายงาน รายงานไม่ผูกกับตัวตนใคร

**วัดผลยังไง**

- เขตที่ไม่มีสถานีวัดมีข้อมูลให้ดู โดยวัดจากสัดส่วนเขตที่มีรายงานที่ยังไม่หมดอายุอย่างน้อย 1 รายการในช่วงที่มีฝนตก
- รายงานยังใหม่ตอนส่ง โดยวัดจากค่ามัธยฐานของช่วงห่างระหว่างเวลาที่เห็นกับเวลาที่ส่ง เป้าคือไม่เกิน 30 นาที **(สมมติฐาน)**
- ข้อมูลที่ไม่ถูกต้องเข้าระบบไม่ได้ มี test ครอบคลุมการตอบ 400 ทุกกรณี (เขตที่ไม่รู้จัก ความลึกไม่ใช่จำนวนเต็มหรืออยู่นอกช่วง เวลาในอนาคต) และการตอบ 429 เมื่อส่งเกินจำนวนที่กำหนด
- ไม่มีข้อมูลส่วนบุคคลหลุดลง log หรือ response มี test ยืนยัน
- test เดิมใน `tests/` ยังผ่านทั้งหมด และ `npm run lint` ผ่าน

## Constraints

**ความปลอดภัย (จาก `.claude/skills/security-baseline`)**

- ตรวจ input ทุกตัวใน API handler (`handle()` ใน `src/app.ts`) ห้ามเชื่อข้อมูลจาก client
- ความลึกต้องเป็นจำนวนเต็มหน่วยเซนติเมตร ไม่รับทศนิยม
- จำกัดจำนวนรายงานต่อ IP
- ห้าม log หรือแสดงข้อมูลส่วนบุคคล (เบอร์โทร ชื่อ ที่อยู่ละเอียด) ให้ log เป็น ID แทน จุดสังเกตที่เป็นข้อความอิสระเสี่ยงต่อข้อนี้ที่สุด
- ทุกอย่างที่แสดงต่อสาธารณะต้องบอกว่าเป็นรายงานจากผู้ใช้ ไม่ใช่ประกาศเตือนภัยทางการ และต้องคง `NOTICE` เดิมไว้

**กติกาของ repo**

- เก็บเวลาเป็น UTC และแสดงผ่าน `toBangkokIso`
- นี่เป็นแอปเพื่อการเรียน ข้อมูลเป็นข้อมูลสมมติ ห้ามนำเสนอเป็นบริการเตือนภัยจริง
- ใช้ Node.js 22 ขึ้นไป TypeScript และ vitest ตามที่มีอยู่

**งบ**

- ไม่ใช้บริการภายนอกหรือฐานข้อมูลที่มีค่าใช้จ่าย เก็บรายงานไว้ในหน่วยความจำก่อน **(สมมติฐาน)**
- ไม่เพิ่ม dependency ถ้าไม่จำเป็น

**สิ่งที่ห้ามแตะ**

- **ห้ามส่งหรือลบรายงานที่ระบบจริง** เช่น ROOP TAN JAI Flood Watch (`flood-api.rooptanjai.com`) อ่านด้วย GET ได้อย่างเดียว ข้อนี้รวมถึงตอนทดสอบด้วย
- ห้ามแก้ `data/stations.json` และห้ามเปลี่ยนรูปแบบ response เดิมของ `GET /districts` และ `GET /districts/:id` ให้เพิ่ม field ได้อย่างเดียว
